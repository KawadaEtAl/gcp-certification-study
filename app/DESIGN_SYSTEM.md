# GCP Architecture Explorer — Design & Engineering Standard

今後の週次セクション（Week 2〜24 / PAA）を毎回ゼロから議論せず、一貫した **Google Cloud / Material Design 品質のライトUI** と **基礎から腹落ちする学習設計** で制作するための恒久基準です。

## 0. 制作スコープとメディア役割分担（Week 2 以降の確定方針）

第1週の実学習（PC・スマホ併用＋個人サンドボックス実測）の振り返りに基づき、制作コストと定着効率のバランスを次の通り定める。

- **Web アプリ（`app/`）を正本（メイン教材）とする**：PC・スマホ双方で最も閲覧時間が長いため、Week 2 以降の週次コンテンツは `app/` に一本化する。
- **週次 Markdown ノート（`notes/weekXX-*.md`）は Week 2 以降作成しない**：アプリとの二重管理を避ける。`notes/` は [glossary.md](../notes/glossary.md) や補助メモ用途に留める（第1週ノートはアーカイブとして保持）。
- **Anki（`anki/cards/weekXX.json`）は継続作成する**：今後本格運用しながら、**第2週〜第3週の完了時点で運用方針を再検討**する。
- **GCP Console スクリーンショットは重要画面のみに厳選する**：全 Part 必須にはせず、操作・設定箇所の把握に効く重要画面だけ撮影・掲載する。

## 1. 学習体験の基本構造（全体地図 → ストーリー × チャート式 × ビジュアル探索）

### 週の冒頭：Part 0（全体マップ＆前提ワード）
- 各週の最初に必ず **「Part 0：今週の全体マップ（静的な骨格図）＋前提ワード 5〜8 語」** を 1 枚置く。
- 個別論点や 4 択例題に入る前に、「登場するエンティティ同士の位置づけ」と「知っておくべき基礎語」を一望できるようにする。

### 各単元（Part 1〜4）の基本 5 要素
各単元は以下を基本構成とし、「なぜ今これを学ぶのか」が一貫したプロジェクト物語でつながるようにする。

0. **ストーリー導入（Story Brief）**：共通の架空プロジェクト（社内製品マニュアル回答アプリ等）の続きとして、「① 依頼・状況 → ② 作りたいもの → ③ 直面した課題」の 3 点をステージ上部に配置する（ネイティブ `<details open>` で折りたたみ可能）。解説タブ末尾には次話への橋渡し（`nextBridge`）を置く。
1. **例題（Chart-Style Hook）**：試験風の短いシナリオ 4 択を最初に提示し、選択即判定＋誤答理由まで解説。
2. **ビジュアル（骨格図ベース＋インタラクティブ厳選）**：
   - **基本は「静的な骨格図」**（色分け＋凡例つきのシンプルな階層・関係図）とし、全体感と要素間の関係を最速で掴める密度に抑える。
   - **ステップ再生・スライダー等のインタラクティブ図は、時間変化・状態遷移・トラフィック切替などが本質の単元だけに厳選**する（全 Part 必須にしない）。**複数単元を単一の固定箱テンプレートに押し込めない。**
3. **インスペクタ（Live Inspector）**：図のアクティブなステップ／ノード／イベントと連動し、KV 表＋実物 JSON（コピー可能）を表示（※静的骨格図中心の単元では、タップ対象ノードの要点解説や設定例など軽量な連動でよい）。
4. **深掘り解説 ＆ ラボ準備**：思考のチャート（3 ステップ）、2〜3 文単位で区切った解説、ミニ確認、条件反転ポイント、次話への橋渡し、公式ドキュメントリンク、そして末尾に **4 ステップ定着ループ（事前予測 3 問 → 手書き作図＆AI 添削 → 個人サンドボックス最小実測 → メモなし音声説明）** と **「実機で踏みがちな裏の登場人物／設定階層」**（例：ビルド用デフォルト SA、インスタンス設定の 3 階層など）を 1 項目配置する。

### 説明の粒度・直感の橋渡し原則（柔軟性プロビソ付き）
第2週以降の解説テキストは、以下 3 点を基本ルールとして備える。

1. **前提語のインライン展開**：初出のクラウド・Web 基礎語（例：コンテナイメージ、リビジョン、インスタンス、Pub/Sub 等）は用語集リンク任せにせず、本文側で「一言＋身近な比喩」を添える。
2. **「なぜ成立する／なぜこの設計か（Why）」の明示**：ブラックボックスになりやすい仕組みは、信頼の根拠・設計理由（例：なぜ秘密鍵なしで認証が成立するか、なぜその仕組みが標準出口なのか）を言語化する。
3. **抽象語の具体化**：「呼び出し元」「設定階層」等の抽象語は、初出時に具体例 2〜3 件や階層リスト（例：クォータ／サービス／リビジョン）を必ず併記する。

> **柔軟性のただし書き**：上記の 5 要素および説明フォーマットはあくまで基本型とする。単元の性質上、この型に当てはめない方が理解しやすい場合は、**形式への統一よりも「理解のしやすさ」を最優先に構成を柔軟に変えてよい**。

## 2. ビジュアル言語・タイポグラフィ（Google Light 基準）

- **カラーシステム（Light First）**
  - Canvas / Surface：`#ffffff` / `#f8fafd` / `#f1f4f9`（枠線の入れ子を避け、余白と面で階層を作る）
  - Primary Accent（Google Blue）：`#0b57d0` / `#1a73e8`
  - Selected Surface（Material Active Pill）：`#d3e3fd`（文字色 `#041e49`）
  - Semantic Colors（意味付け専用・選択色と混同しない）：
    - Control Plane / 管理系：Indigo `#4338ca`
    - Ingress / 通信入口：Cyan `#0891b2`（Control Plane と明確に色分離）
    - Data Plane / 正常・許可：Emerald `#137333`
    - Async Lag / 警告・遅延：Amber `#b06000`
    - Denied / 漏えい・危険：Crimson `#c5221f`
- **AI スロッピー表現の禁止事項**
  - カード左端の太い色帯（`border-left: 3.5px solid ...`）は **使用禁止**。均一な 1px 枠＋番号バッジまたは控えめなラベルで構造を示す。
  - `CHART-STYLE HOOK` / `EVENT FLOW TRACE` / `READ-ONLY` のような **等幅大文字の英語アイブロウ装飾は禁止**。自然な日本語見出しを使う。
  - 等幅フォント（`--font-mono`）は **コード・IAM ロール・URL・時刻・JSON のみに限定**する。
- **タイポグラフィ**
  - 見出し `H1` のウェイトは `600` 前後（過剰な `850` 極太は避ける）。
  - 本文・選択肢・解説はモバイルで `16px`（行間 `1.65`）、デスクトップで `14px〜15px`。
  - 本文中のロール名・権限・コマンド等はインラインコード（背景 `#f1f3f4`・角丸 `4px`・等幅）でマークアップし、長い段落は 2〜3 文ごとに改行する。
  - 不自然な日本語折り返し対策として `word-break: auto-phrase; text-wrap: balance;` を使い、長い識別子（`roles/...` 等）には `/`・`.` の後ろに `<wbr>` を挿入する。
  - JSON 表示（`pre`）は `white-space: pre-wrap; overflow-wrap: anywhere;` で右端見切れを防ぎ、ヘッダーに **コピーボタン** を置く。

## 3. レイアウト & ナビゲーション基準

- **デスクトップ（`>= 1080px`）**
  - 3 ペイン構成：`1080px〜1439px` は `224px / minmax(0, 1fr) / 356px`、`>= 1440px` は `256px / minmax(0, 1fr) / 400px` とし、中央の図解キャンバス幅を最優先で確保する。
  - 左サイドバーは枠付きカードをやめ、**Material ナビゲーションリスト**（枠線なし、選択時は角丸ピル `#d3e3fd`）。項目が 6 件未満の週では不要な領域フィルタチップを置かない。ロードマップ一覧は折りたたみ（`<details>`）にする。
  - 右ペインのタブバーは **4 等分グリッド**（`grid-template-columns: repeat(4, minmax(0, 1fr))`）で「例題 / インスペクタ / 解説 / ラボ」の 4 タブが見切れずに収まるようにする。選択状態は `::after` の `border-block-end` で描画（forced-colors 対応）。
- **モバイル（`< 680px` / iPhone）**
  - ヘッダーは 1 行固定（`GCP Explorer`＋進捗ピル）。
  - シナリオチップは **1 行横スクロール**（縦積みで図を押し下げない）。ラベルは短縮する（例：`正常` / `actAs なし` / `Invoker なし` / `Viewer なし`）。
  - 下部固定ドックを **全 Part 共通で表示**し、ボタン／セレクトは `min-height: 48px`、`env(safe-area-inset-bottom)` 対応、コンテンツ下部に `padding-bottom: 108px` を確保する。

## 4. 操作部品の統一基準

- **再生コントロール（`<PlaybackBar />`）**
  - 時間変化・状態遷移を扱うインタラクティブ図解を採用した Part では、**図解キャンバスの直下** に 1 本のバーを配置する（別カードへ分裂させない）。静的骨格図の Part では不要な再生バーを置かない。
  - 並び順：`再生 / 一時停止` → `前へ / ステップ`（または `+20分` / `+30分`）→ スライダー（時間軸がある場合）→ `速度` → `リセット`。
  - 表記は日本語に統一（`再生` / `一時停止` / `ステップ` / `+20分` / `+30分`）。
- **シナリオチップの選択状態**
  - 選択中スタイルは常に `#d3e3fd` 背景＋`✓` アイコンに統一する。
  - 「正常 / 設定ミス / 警告」の意味は先頭の **8px セマンティックドット** で示し、選択色と危険色を混同させない。
- **設定トグル・スコープ選択**
  - ON/OFF 切替は標準スイッチ（`role="switch"`）、3 択スコープはセグメントボタンを使い、「プリセット」と「手動で調整」を見出しで明確に分ける。

## 5. SVG 図解と一貫性チェック基準

- **デスクトップ SVG（`viewBox="0 0 820 ..."`）**
  - 1280px 画面で描画後の実寸が **ノード名 12px 以上・副ラベル 11px 以上** になるよう、SVG 内フォントサイズはノード名 `15.5px〜16px`・副ラベル `13px〜14px` を基準とする。
  - 右端に最低 `24px` の安全余白を取り、端の要素が潰れないようにする。
  - パケットピルは配線ギャップ内に収め、ノード枠・タイトル・判定ゲート（ひし形）に絶対に重ねない。
- **iPhone 専用 1:1 縦型 SVG（`useIsMobile()` / `viewBox="0 0 380 ..."`）**
  - 横長図を縮小表示せず、380px 幅の縦型 SVG を用意して **約 1:1 スケール（実寸 13〜15.5px）** を実現する。
  - 階層ツリー等では、親からすべての子リソースへ接続線が正しく伸びていること。
- **内容の一貫性（Desktop / Mobile / Inspector / JSON）**
  - リソース名（例：`manual-docs`）、数値（例：集計ラグ `55分`）、コンテナ枠ラベル（例：`Cloud Run Service (Private)`）は、デスクトップ図・モバイル図・インスペクタ・JSON の 4 箇所で完全に一致させる。

### GCP Console 実画面スクリーンショット基準

- **対象選定**: 全 Part 必須ではなく、**操作箇所・設定構造の理解に直結する重要画面のみ**を厳選して撮影・掲載する。
- **配置場所**: 「解説」タブ内に `<ConsoleScreenGallery />` で掲載し、サムネイルクリックでネイティブ `<dialog closedby="any">` の拡大モーダルを開く（4 タブ構成は維持する）。
- **保存先（単一ソース）**: `app/public/screenshots/weekXX/<slug>.png` に保存し、アプリからは `./screenshots/weekXX/<slug>.png` で参照する（Week 1 ノート等から参照する場合も同一ソースを使う）。
- **撮影＆個人情報マスク**: `.agents/skills/gcp-console-screenshot/SKILL.md` の手順に従い、`1280×800`・`?hl=ja` のビューポートで撮影直前に DOM をダミー値（`gcp-study-sandbox` / `study-admin@example.com` / `Taro Yamada` / `123456789012`・アイコン置換）へ書き換えてから保存する。実プロジェクト名やメールアドレス等の置換表は必ず Git 管理外の `local/gcp-mask-config.json` に置く。

## 6. 完了前の必須検証

新セクション実装時は必ず以下を実行してから完了報告する。
1. `cd app && npm run build`（`tsc -b && vite build` がエラーゼロ）
2. Chromium で **Desktop（1280×860）** と **iPhone（390×844）** の実画面スクリーンショットを撮影し、目視で以下を確認：
   - 横はみ出しゼロ（`scrollWidth === innerWidth`）
   - 文字切れ・不自然な折り返し・要素重なりゼロ
   - タブ 4 件・再生バー・数値・リソース名の完全一致
