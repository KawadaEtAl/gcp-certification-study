# 実習用の架空システム

架空の製品マニュアルについて、根拠を添えて答える小さなアプリを想定する。まずは固定文書を返せばよい。検索やモデル連携がなくてもインフラの学習は進められる。

| 要素 | 役割 | 確認すること |
| --- | --- | --- |
| Cloud Run | 入口とバックグラウンド処理 | 誰が呼べるか、実行時のID、リビジョン |
| Cloud Storage | 合成文書と版付きスナップショット | オブジェクト権限、世代、ライフサイクル |
| Firestore | 利用する版と処理済みイベントの状態 | 版を切り替える条件と再試行時の衝突 |
| Cloud Tasks | 非同期呼び出し | 再試行、同じイベントの重複、呼び出し元のID |
| Secret Manager | 必要な場合だけ、実習専用の値を供給 | 秘密値へのアクセスを許す主体 |
| Cloud Build・Logging・Monitoring | 変更をビルドし、実行結果を観測 | リビジョンとログの対応、エラー検知、切り戻し |

## 第2週以降の標準演習・定着ループ（4 ステップ）

第1週で最も理解・定着に効いた流れを、第2週以降の標準テンプレートとする。各週の教材末尾（ラボタブ）にも同じ 4 ステップと「実機で踏みがちな裏の登場人物／設定階層」を配置する。

1. **事前予測（3 問）**：手を動かす前に、挙動・失敗箇所・境界条件を 3 問それぞれ一言で予想して記録する。
2. **手書き作図＆AI 添削**：今週のエンティティ・権限・通信経路・状態遷移を自分の手で図に描き、認識のズレを先に洗い出す。
3. **個人サンドボックスでの最小コマンド実測**：既存の個人サンドボックス（`week01-manual-api` 等）を継続・発展させ、最小構成で予想と実測を比較する。あわせて「裏の登場人物（ビルド用 SA 等）や複数階層の設定（クォータ／サービス／リビジョン等）」も意識して観測する。
4. **メモなし音声説明＆記録**：設定やメモを見ずに自分の言葉で仕組みと設計理由を説明し、予測との差分・詰まった点・片付け状況を [PROGRESS.md](../PROGRESS.md) と [CHECKLIST.md](../CHECKLIST.md) に記録する。

## 第1週 IAMとCloud Run

**目標**は、呼び出し権限、デプロイ時のサービスアカウント利用権限、実行時のデータ権限の違いを観測で説明すること。所要の目安は読解と実習を合わせて2〜3時間。

1. [Cloud RunのサービスID](https://cloud.google.com/run/docs/securing/service-identity)を読み、入口の呼び出し元、デプロイ主体、ランタイムサービスアカウントを図に描く。
2. Google Skillsのラボまたは個人の学習用プロジェクトで、権限と課金対象を確認する。バケットに合成テキストを一つ置き、Cloud Runに実行用サービスアカウントを割り当てる。読み取りロールは対象バケットに絞る。
3. 認証された呼び出しを一度実行し、読み取り成功を確認する。アプリの書き込み操作は拒否されることを別に確認する。環境の制約で確認できない場合は、未確認の操作と理由を記録する。
4. 「権限を削るとどの操作が失敗するか」「JSON鍵が不要になる仕組み」を設定を見ずに説明する。リソースを片づけて、課金対象が残っていないか確認する。

記録する情報は、試した操作、予測、結果、根拠、次に切り分ける点。認証情報や実環境の識別子は記録例に使わない。

## Terraform演習

第11週に、架空のCloud Storageバケット一つを定義し、環境依存の名前は変数にする。入力を一つ変更して作成・更新・置換の違いをplanで確認する。適用する場合は対象が個人用の演習環境であることを確認し、適用後に実体と差分を確認する。最後に演習用リソースを片づける。

記録する問いは「設定とstateと実体がずれたら何を見るか」「複数人で実行するなら状態の保護、権限、レビューをどう設計するか」。個人メモには実行結果の要約を残す。
